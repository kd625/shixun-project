# 虚拟仿真实训教学管理及资源共享云平台设计

## 背景

本项目基于现有 RuoYi Vue 代码库实现一个可演示的实训作业项目。需求文档要求建设“虚拟仿真实训教学管理及资源共享云平台”，用于对虚拟仿真实训教学场所、设施设备和实训资源进行跨专业、跨院校、跨地域统筹管理，并提供教学过程监控分析、资源汇聚分配、管控统计等能力。

现有项目结构为：

- `kevin-server/`：Spring Boot / RuoYi 多模块后端。
- `kevin-web/`：Vue 2 / Element UI 前端。
- `kevin-doc/requirement.md`：实训作业需求文档。

本设计采用“RuoYi 风格手写精简业务 + 演示聚合页”的方案：核心业务使用真实表、接口和后台 CRUD；门户、数据大屏、监控和效能页面围绕业务数据做演示级聚合。

## 目标

1. 实现一个能在课堂或答辩现场完整演示的平台。
2. 覆盖资源共享和教学实训两条真实业务闭环。
3. 保留 RuoYi 原有登录、权限、菜单、日志、用户和系统监控能力。
4. 使用本地 MySQL + Redis 作为标准演示环境。
5. 将新增业务表、菜单、权限、字典和演示数据统一追加到 `kevin-server/sql/ry_20260417.sql`，便于一次初始化数据库。

## 非目标

1. 不做真实硬件设备采集、物联网协议接入或实时视频流。
2. 不重写 RuoYi 的认证、权限、用户、角色、菜单和日志体系。
3. 不实现复杂的学生账号体系、学籍管理或在线考试系统。
4. 不做跨校真实资源调度，只用演示数据体现跨专业、跨院校、跨地域场景。

## 模块范围

### 前台门户

前台门户面向社会人士和普通用户，提供以下页面：

- 平台首页：展示平台定位、核心指标、推荐资源、开放实验室、新闻公告。
- 新闻公告：展示公告通知和新闻资讯。
- 资源中心：按虚拟仿真、视频、音频、文档等类型展示资源。
- 实训实验：展示可开放的实训实验。
- 实验室：展示实验室开放状态、容量、位置和负责人。
- 共享开放：展示开放资源和实验室，并提供申请入口。
- 数据大屏：展示平台资源、设备、实训和开放共享成效。

### 后台管理

后台管理使用 RuoYi 菜单体系新增业务菜单：

- 资源管理：实验室、仿真设备、实训资源、共享申请。
- 实训管理：课程管理、实训实验、教学计划、过程结果。
- 数据概览：概览统计、实训分析、数据导出。
- 监控管理：设备监控、资源监控、教学监控。
- 效能管理：资源利用率、实验完成率、开放共享成效。

真实 CRUD 页面优先覆盖：实验室、仿真设备、实训资源、共享申请、课程、实训实验、教学计划、过程结果。

数据概览、监控管理、效能管理以聚合接口和业务状态字段支撑演示，不做真实硬件接入。

### 复用模块

以下能力沿用 RuoYi：

- 登录、验证码、JWT、权限注解。
- 用户、角色、菜单、部门、岗位、字典、参数。
- 操作日志、登录日志、服务监控、缓存监控、定时任务。
- Excel 导入导出工具和通用分页查询。

## 数据模型

新增 8 张业务表。

### `vt_lab` 实验室

用途：管理虚拟仿真实训教学场所。

核心字段：

- 实验室名称
- 所属院校或院系
- 地点
- 容量
- 开放状态
- 负责人
- 联系方式
- 简介

### `vt_device` 仿真设备

用途：管理实验室内的仿真设备。

核心字段：

- 设备名称
- 设备编号
- 所属实验室
- 设备类型
- 运行状态
- 在线状态
- 最近检测时间
- 备注

### `vt_resource` 实训资源

用途：管理虚拟仿真、视频、音频、文档等资源。

核心字段：

- 资源名称
- 资源类型
- 所属专业
- 适用课程
- 封面或附件地址
- 共享状态
- 浏览量
- 收藏量
- 简介

### `vt_share_apply` 共享开放申请

用途：管理社会人士或外部单位对资源、实验室的开放共享申请。

核心字段：

- 申请人
- 手机号
- 单位
- 申请类型
- 关联资源或实验室
- 预约时间
- 使用人数
- 申请状态
- 审核意见

### `vt_course` 课程

用途：管理实训课程。

核心字段：

- 课程名称
- 专业方向
- 课时
- 授课教师
- 课程状态
- 课程简介

### `vt_experiment` 实训实验

用途：管理具体实训实验。

核心字段：

- 实验名称
- 关联课程
- 关联资源
- 难度
- 预计时长
- 开放状态
- 实验简介

### `vt_teaching_plan` 教学计划

用途：管理课程与实验的教学安排。

核心字段：

- 计划名称
- 关联课程
- 关联实验
- 班级或对象
- 计划开始时间
- 计划结束时间
- 计划状态
- 负责人

### `vt_training_record` 过程结果

用途：记录学员参与实训实验的过程和结果。

核心字段：

- 关联计划
- 学员姓名
- 学号或编号
- 开始时间
- 结束时间
- 完成状态
- 得分
- 用时
- 评价

### 关系

- 实验室 1:N 仿真设备。
- 课程 1:N 实训实验。
- 实训资源可关联到实训实验。
- 共享开放申请可关联资源或实验室。
- 教学计划关联课程和实验。
- 过程结果关联教学计划。

## 接口设计

接口按 RuoYi 风格实现，Controller 位于 `ruoyi-admin`，Domain、Mapper、Service 位于 `ruoyi-system`。

后台管理接口：

- `/virtual/lab`
- `/virtual/device`
- `/virtual/resource`
- `/virtual/shareApply`
- `/virtual/course`
- `/virtual/experiment`
- `/virtual/plan`
- `/virtual/record`
- `/virtual/dashboard`

前台门户接口：

- `/portal/home`
- `/portal/news`
- `/portal/resources`
- `/portal/experiments`
- `/portal/labs`
- `/portal/share`
- `/portal/screen`

后台 CRUD 接口遵循 RuoYi 现有约定：列表分页、详情、新增、修改、删除、导出。门户接口以查询和申请为主。

## 页面设计

### 后台 CRUD 页面

每个核心业务页面使用 RuoYi 现有列表页模式：

- 顶部搜索表单。
- 表格列表。
- 新增、修改、删除、导出按钮。
- 弹窗表单。
- 状态字段使用字典或标签展示。
- 关联字段用下拉框选择。

### 数据大屏

数据大屏使用 ECharts 展示：

- 资源总量、实验室数量、设备数量、实训参与人数。
- 资源类型占比。
- 设备在线、离线、维护状态统计。
- 近 7 天预约和实验趋势。
- 实验完成率、平均得分、资源利用率。
- 开放共享申请状态分布。

### 门户页面

门户页面直接进入业务内容，不做营销型落地页。首页首屏展示平台名称、关键指标、推荐资源和开放入口；资源、实验、实验室列表支持筛选和详情查看；共享开放页支持提交申请。

## 演示流程

推荐按 6 分钟左右演示：

1. 登录系统，首页展示平台定位、资源数量、实验室开放情况和实训趋势。
2. 进入门户资源中心，查看虚拟仿真、视频、音频、文档等资源。
3. 进入实验室和共享开放页面，查看开放实验室并提交申请。
4. 进入后台资源管理，维护实验室、设备、资源，并审核共享申请。
5. 进入后台实训管理，维护课程、实验、教学计划和过程结果。
6. 打开数据大屏，展示资源分布、设备状态、实验完成率、预约趋势和效能指标。
7. 补充展示 RuoYi 自带用户、角色、菜单、日志和服务监控，说明系统具备权限、审计和运维基础。

## 验证标准

后端验证：

- 在 `kevin-server/` 执行 `mvn test`。
- 至少确认所有模块编译通过，若测试为空也要确认 Maven 没有编译错误。

前端验证：

- 在 `kevin-web/` 执行 `npm run build:prod`。
- 确认生产构建通过。

数据库验证：

- 导入更新后的 `ry_20260417.sql` 和 `quartz.sql`。
- 启动 MySQL、Redis、后端和前端。
- 使用管理员账号登录后能看到新增菜单。

演示验证：

- 前台门户、后台 CRUD、数据大屏页面无空白。
- 实验室、设备、资源、申请、课程、实验、计划、结果能查询、新增、编辑、删除。
- 共享申请可从门户提交，并在后台看到状态。
- 数据大屏能展示业务表聚合数据。

## 风险与处理

1. 业务范围较多，字段必须保持精简，优先保证演示闭环。
2. 前台门户和后台管理都要改动，实施时应先完成 SQL 和后端接口，再接前端页面。
3. 数据大屏不接真实硬件，页面文案应表达为“平台监控统计”，避免误导为实时采集。
4. SQL 追加到既有初始化文件时要注意菜单 ID、字典 ID 和业务表名不与 RuoYi 原表冲突。
5. 当前项目使用 RuoYi 基座，新增代码应遵循现有包名、命名、权限注解、分页和导出风格。
